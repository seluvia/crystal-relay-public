Crystal Relay Release Change Record

Purpose:
- Track in-progress release notes before a test build or release build.
- Use the Added / Changed / Removed sections to draft CHANGELOG.txt and GitHub release notes.
- Keep entries user-facing and short enough to reuse in public notes.
- This file is for internal release prep and record-keeping. It should stay out of the public repo unless you explicitly choose otherwise.

Current Baseline:
- Last published version: v3.1.8
- Current working source version: v3.1.9

How To Use:
1. Add new lines under Added, Changed, or Removed while work is happening.
2. Before a release build, review this file and trim duplicates or dev-only wording.
3. Move the final public-facing summary into CHANGELOG.txt and the GitHub release notes.
4. After the release is published, update the baseline version and clear the pending draft section for the next release.
5. Retired release drafts (versions that already shipped) are removed from the working area once their content is captured in CHANGELOG.txt. The release checklist is always kept.

- Improved VRChat + Crystal Relay restart rejoin so private/group/friends instance launch targets are passed back to VRChat in the raw format it expects.

Release Checklist:
- Update the app version in VrcTwitchOscBridge.csproj (and CrystalRelayUpdater.csproj).
- Update CHANGELOG.txt with the final user-facing notes; append a `v<version> beta <N>` section for each beta, and add a fresh `v<version>` rollup entry above the betas when the stable ships.
- Run a test build first if the change is visual, risky, or user-requested.
- Run the release build and verify the package output.
- Sync and verify the private repo first if the release is meant to go to GitHub.
- Sync and verify the public repo only after the private repo is confirmed good.
- Publish or update the matching GitHub release asset with the public release package/file.
